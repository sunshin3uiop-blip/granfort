# GRANFORT

Простая адаптивная вёрстка по макету Figma. HTML, CSS (flex/grid), JavaScript и небольшой обработчик заявок на PHP. Без библиотек, базы данных и анимаций.

## Открыть

Нужен PHP 8 или новее. Из папки проекта выполните:

```sh
php -S 127.0.0.1:3000 -t dist
```

Откройте `http://127.0.0.1:3000`. Сборка и установка зависимостей не нужны. Фотографии и шрифты хранятся локально в `dist/assets`.

Без PHP можно открыть `dist/index.html` для просмотра вёрстки, но отправка заявок работать не будет. GitHub Pages также не выполняет PHP.

## Vercel

В корне репозитория есть `vercel.json`. Он запускает `node scripts/build-vercel.cjs` и публикует папку `vercel-public`. Скрипт берёт HTML, CSS, JavaScript, шрифты и фотографии из `dist`; PHP-исходники в статическую публикацию не попадают.

При импорте этого репозитория в Vercel укажите:

- **Root Directory** — корень репозитория, где лежит `vercel.json`; не `dist`.
- **Framework Preset** — `Other`.
- **Build Command** — `node scripts/build-vercel.cjs` (берётся из конфигурации).
- **Output Directory** — `vercel-public` (берётся из конфигурации).

Если проект уже создан, проверьте Root Directory и уберите старые ручные настройки сборки, противоречащие `vercel.json`, затем выполните Redeploy.

Эта настройка публикует **только внешний вид сайта**. Форма заявки и админка в таком статическом деплое не работают. Для них нужен PHP-сервер с постоянным хранилищем. Текущий бэкенд использует `data/requests.jsonl`, файл пароля и PHP-сеансы, поэтому его нельзя просто перенести в обычную статическую публикацию Vercel.

Vercel поддерживает запуск произвольного кода через Container Runtime, но для размещения этого PHP-бэкенда там потребуется адаптировать хранение заявок, пароля и сеансов к внешнему постоянному хранилищу. Для сохранения текущей простой версии можно разместить весь проект на PHP-хостинге, назначив `dist` корнем сайта.

Документация: [настройка Output Directory](https://vercel.com/docs/project-configuration/vercel-json#outputdirectory), [Container Runtime](https://vercel.com/docs/functions/runtimes/container), [файловая система Vercel Functions](https://vercel.com/docs/functions/runtimes#file-system-support).

## Файлы

- `dist/index.html` — разметка.
- `dist/style.css` — стили для компьютера и телефона.
- `dist/script.js` — поиск по услугам, меню, вопросы, выбор специалиста и информационные окна.
- `dist/request.php` — принимает форму, проверяет поля и записывает заявку.
- `dist/admin.php` и `dist/admin.css` — вход в админку и просмотр заявок.
- `data/requests.jsonl` — сохранённые заявки; создаётся при первой отправке и не попадает в Git.

## Как работает PHP

Нажмите на карточку услуги или кнопку связи в шапке. Заполните имя и телефон, выберите услугу и нажмите «Оставить заявку». Форма отправляется обычным POST-запросом в `request.php`.

PHP проверяет имя, телефон и выбранную услугу. Если всё заполнено правильно, добавляет одну строку JSON в `data/requests.jsonl` и показывает сообщение об успехе. Старые заявки остаются в файле. Если данные неверные или запись не удалась, показывает ошибку.

На хостинге корнем сайта должна быть папка `dist`. Папка `data` должна оставаться за её пределами, а процесс PHP должен иметь право записи в неё. Отправки писем нет.

## Админка

Откройте `http://127.0.0.1:3000/admin.php`. Если сервер работает на другом порту, используйте его: например, `http://127.0.0.1:3001/admin.php`.

При первом открытии создайте пароль длиной не меньше 8 символов и повторите его. После этого появится таблица с датой, именем, телефоном и услугой. Новые заявки показываются первыми. Кнопка «Обновить» перечитывает файл, а «Выйти» завершает вход.

Пароль сохраняется в виде хеша в `data/admin-password.hash`. Общего пароля по умолчанию нет. На публичном хостинге создайте пароль сразу после установки. Папка `data` не попадает в GitHub. Для переноса уже полученных заявок оставьте существующий `data/requests.jsonl` на месте.

Если пароль забыт, остановите сервер, удалите только `data/admin-password.hash`, запустите сервер и снова откройте админку. Заявки удалять не нужно. После смены пароля старые сеансы входа перестанут подходить.

В Windows можно нажать правой кнопкой на папку `dist` в VS Code, выбрать **Open in Integrated Terminal** и запустить сервер прямо из неё:

```powershell
& "C:\php\php.exe" -S 127.0.0.1:3001 -t .
```

Тогда сайт находится по адресу `http://127.0.0.1:3001/index.html`, а админка — `http://127.0.0.1:3001/admin.php`. Live Server на порту 5500 не выполняет PHP.

## Что работает

Навигация по разделам, поиск по трём услугам, форма заявки в карточках услуг и кнопке связи, сохранение заявок через PHP, админка с паролем и таблицей заявок, раскрытие ответов, выбор специалиста, адрес на карте, электронная почта. Окна с информацией о доставке, возврате, акциях и документах явно показывают, что соответствующий контент ещё не предоставлен.

## Отличия от макета

Мелкие иконки и монограмма упрощены: лимит Figma MCP закончился до их выгрузки. Основные фото, карта, шрифты, цвета, десктопная и мобильная композиции взяты из макета. Добавленные ответы в FAQ — демонстрационный текст, его нужно согласовать перед коммерческим использованием.

## Проверка

Проверены синтаксис JavaScript и PHP, локальные ссылки на ресурсы, якоря и отсутствие CSS-анимаций/переходов. Обработчик PHP проверен HTTP-запросами: сохранение нескольких заявок, неверные поля, неправильный метод запроса, недоступность файла заявок через сайт и ошибка записи. Админка проверена на создание пароля, вход и выход, закрытый доступ без входа, чтение заявок, безопасный вывод текста, сброс пароля и ошибки чтения. Визуальная проверка в браузере недоступна в текущем окружении.
