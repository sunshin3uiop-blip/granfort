# GRANFORT

Адаптивный сайт по макету Figma: HTML, CSS и JavaScript, без анимаций и фреймворков.

Есть два варианта бэкенда:

- **На Vercel** — JavaScript-функции и постоянное хранилище Upstash Redis. Форма и админка работают по адресам `/request.php` и `/admin.php`: Vercel направляет эти запросы в функции.
- **Локально на PHP** — исходная учебная версия с сохранением заявок в `data/requests.jsonl`.

## Разместить на Vercel

1. Импортируйте этот GitHub-репозиторий в Vercel. **Root Directory** — корень репозитория, где лежат `package.json` и `vercel.json`, не папка `dist`.
2. Выберите **Framework Preset: Other**. Build Command (`node scripts/build-vercel.cjs`) и Output Directory (`vercel-public`) уже указаны в `vercel.json`.
3. В Vercel откройте раздел **Storage / Marketplace**, создайте или подключите **Upstash Redis** и свяжите его с этим проектом. Нужны REST URL и токен с правом записи. После подключения интеграция может добавить переменные автоматически.
4. В **Settings → Environment Variables** проверьте переменные:

   | Переменная | Значение |
   | --- | --- |
   | `UPSTASH_REDIS_REST_URL` | REST URL вашей базы Redis |
   | `UPSTASH_REDIS_REST_TOKEN` | Токен этой базы с правом записи |
   | `ADMIN_PASSWORD` | Ваш пароль админки, не меньше 12 символов |

   Также поддерживаются имена `KV_REST_API_URL` и `KV_REST_API_TOKEN`, если интеграция создала их вместо `UPSTASH_...`.

5. Примените переменные к **Production** и выполните **Redeploy**. Если нужна работающая Preview-версия, подключите хранилище и переменные также к Preview.
6. Сайт открывается по корню выданного домена, админка — по адресу `https://ваш-домен/admin.php`. На Vercel используйте пароль из `ADMIN_PASSWORD`; страница создания пароля относится только к локальной PHP-версии.

Сборка копирует HTML, стили, JavaScript, фотографии и шрифты из `dist` в `vercel-public`. PHP-исходники, `.env`, папка `data` и серверный JavaScript не публикуются как статические файлы. Функции из `api` Vercel собирает отдельно.

### Как хранятся данные на Vercel

Заявки добавляются в список Redis, а сеансы администратора хранятся там же с временем жизни 8 часов. Перезапуск функции или новый деплой не удаляет заявки. После выхода сеанс удаляется; смена `ADMIN_PASSWORD` и новый деплой делают старые сеансы недействительными.

Production, Preview и локальная JavaScript-версия используют разные ключи внутри одной базы. По умолчанию ключи начинаются с `granfort:production:`, `granfort:preview:` или `granfort:development:`. Для другого проекта в той же базе можно задать `GRANFORT_STORAGE_PREFIX`.

Без настроенного хранилища форма сообщает об ошибке сохранения, а не показывает ложный успех. Админка показывает, чего не хватает для настройки. Пароль и токены задаются только в переменных окружения; готового общего пароля в проекте нет.

## Локально: версия для Vercel

Нужен Node.js 24. Зависимостей и установки библиотек нет.

1. Скопируйте `.env.example` в `.env` и заполните настройки Redis и свой `ADMIN_PASSWORD`.
2. Из корня проекта запустите:

   ```sh
   npm run dev
   ```

3. Откройте `http://127.0.0.1:3001/index.html`, админку — `http://127.0.0.1:3001/admin.php`.

Команда сама подготавливает статические файлы и запускает форму и админку. Если не настроить `.env`, внешний вид сайта будет доступен, а отправка и вход сообщат о недостающих настройках.

### Перенести старые заявки из PHP в Redis

Если заявки уже есть в `data/requests.jsonl`, заполните `.env` данными той базы, которая подключена к Vercel, и выполните:

```sh
npm run import -- data/requests.jsonl --production
```

Если файл находится в другом месте, укажите его фактический путь. Импорт добавляет заявки в Production, не удаляет исходный файл и не удваивает строки при повторном запуске. Содержимое заявок и токены не выводятся в терминал.

## Локально: исходная PHP-версия

Нужен PHP 8 или новее. Из корня проекта:

```sh
php -S 127.0.0.1:3000 -t dist
```

В Windows можно нажать правой кнопкой на папку `dist` в VS Code, выбрать **Open in Integrated Terminal** и запустить сервер прямо из неё:

```powershell
& "C:\php\php.exe" -S 127.0.0.1:3001 -t .
```

Откройте `http://127.0.0.1:3001/index.html`, админку — `http://127.0.0.1:3001/admin.php`. Live Server на порту 5500 не выполняет PHP.

В этой версии форма отправляется обычным POST-запросом в `request.php`. PHP проверяет имя, телефон и услугу, добавляет JSON-строку в `data/requests.jsonl` и показывает результат. Папка `data` находится на уровень выше папки с `request.php`.

При первом открытии PHP-админки задайте пароль от 8 символов. Его хеш сохраняется в `data/admin-password.hash`. Если пароль забыт, остановите PHP-сервер, удалите только этот файл и создайте пароль заново. Заявки удалять не нужно.

На обычном PHP-хостинге назначьте `dist` корнем сайта и дайте процессу PHP право записи в соседнюю папку `data`. Конфигурация Vercel для этого варианта не используется. GitHub Pages не выполняет ни PHP, ни функции Vercel.

## Файлы

- `dist/index.html`, `dist/style.css`, `dist/script.js` — внешний вид и взаимодействия.
- `dist/admin.css` — стили админки.
- `api/request.js`, `api/admin.js` — обработчики для Vercel.
- `server/` — работа с Redis, HTTP и HTML-страницы функций.
- `scripts/build-vercel.cjs` — подготовка статических файлов.
- `scripts/dev.cjs` — локальный запуск JavaScript-версии.
- `scripts/import-requests.cjs` — перенос старых заявок.
- `dist/request.php`, `dist/admin.php` — локальная учебная версия на PHP.
- `data/` — локальные заявки и пароль PHP-версии; не попадает в Git.
- `.env.example` — пустой пример переменных; настоящий `.env` игнорируется Git.

## Проверка

```sh
npm test
npm run build
```

HTTP-проверки используют отдельное тестовое хранилище: отправка и проверка формы, вход и выход, закрытый доступ к заявкам, вывод текста, страницы таблицы, лимиты запросов, ошибки хранилища и сохранение данных между экземплярами приложения. Настройки Production для тестов не используются.

PHP-версия ранее проверена отдельно через HTTP и проверку синтаксиса. Визуальная проверка в браузере в текущем окружении недоступна.

## Отличия от макета

Мелкие иконки и монограмма упрощены из-за лимита Figma MCP. Основные фото, карта, шрифты, цвета и композиции взяты из макета. Дополнительные ответы в FAQ — демонстрационный текст. Доставка, акции и документы пока содержат заглушки. Отправки писем и страницы покупки нет.

Документация: [Vercel Functions](https://vercel.com/docs/functions/runtimes/node-js), [Upstash REST API](https://upstash.com/docs/redis/features/restapi), [подключение Redis к Vercel](https://upstash.com/docs/redis/howto/vercelintegration).
